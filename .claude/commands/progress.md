# /progress — プロジェクト進捗確認 & 次タスク提案

## 制約（必須）

1. **読み取り専用**: ファイルの変更は一切行わない
2. **事実ベース**: PROGRESS.mdに記載のないタスクを提案しない
3. **簡潔さ**: 長大な進捗ファイルでも、出力はコンパクトにまとめる

## 使用方法

```bash
/progress              # 全体の進捗サマリー + 次タスク候補
/progress summary      # サマリーのみ（簡潔版）
/progress <セクション>  # 特定セクションの詳細（例: /progress セッション管理）
```

## 状態マーカー定義

PROGRESS.mdでは2系統のマーカーが使われる。集計時は以下のマッピングに従う:

| マーカー | 意味 | 集計カテゴリ |
|---------|------|-------------|
| `[x]` | 完了・テスト通過 | 完了 |
| `[-]` | テスト存在するがskip/偽陽性 | 進行中 |
| `[→]` | 作業中 | 進行中 |
| `[ ]` | 未着手・テスト不在 | 未着手 |

## 実行手順

### Step 1: ファイル読み込み

以下のファイルを読み込む:

1. `.claude/PROGRESS.md` — メインの進捗管理ファイル
2. `CLAUDE.md` — プロジェクト概要・ルール参照

### Step 2: 進捗集計 → サマリー生成 → タスク候補抽出

PROGRESS.mdを解析し、以下を一括で処理する:

**集計対象**:
- **TDD進捗**: 各機能セクションのマーカー別件数と完了率
- **計画書進捗**: 各計画書の状態（完了 / 進行中 / 未着手）
- **UI/UXリファクタリング**: 優先度別の残タスク数
- **監査指摘事項**: 未対応の `[ ]` の数

**タスク候補の抽出**:
- PROGRESS.mdの「次のアクション」セクションから優先度別タスクを引用
- 各セクション内の未完了タスク（`[ ]`, `⬜`, `🔄`）を補足として追加

### 引数による出力切り替え

| 引数 | 出力内容 |
|------|---------|
| なし | 全体サマリー + 次タスク候補 |
| `summary` | サマリーのみ（タスク候補は省略） |
| セクション名 | 該当セクションの詳細な進捗と未完了タスク |

## 優先度分類の基準

PROGRESS.mdの「次のアクション」セクションに記載された優先度をそのまま使用する。
セクションに記載のないタスクを補足する場合は以下の基準で分類:

| 優先度 | 基準 |
|--------|------|
| A | 「次のアクション」に明記されたタスク |
| B | `🔄`（作業中）だが未完了のタスク |
| C | `[ ]`（未完了）で特定の機能に紐づくタスク |
| D | リファクタリング、品質改善、テスト補完 |

## タスク候補の表示ルール

1. **PROGRESS.mdの「次のアクション」セクションを最優先でそのまま引用する**
2. 各セクション内の未完了タスクを補足として追加
3. 各候補には**根拠**（セクション名）を併記
4. 候補数は優先度ごとに最大5件まで
5. 会話の`gitStatus`にブランチ情報がある場合、そのブランチに関連するタスクを優先表示
