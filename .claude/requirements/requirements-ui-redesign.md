# UI全面リデザイン 要件定義書（デザイン軸）

**作成日**: 2026-06-11
**TDDフェーズ**: 要件定義
**情報源**: ChatGPT Image2 モックデザイン2点（①シナリオ一覧+詳細分割ビュー、②ホーム）

---

## 1. 概要

### 1.1 目的

アプリ全体のUIをモックデザインを軸に刷新する。最重要の体験変更は、シナリオ一覧画面の主目的を「特定シナリオの検索」から**「次にプレイするシナリオの探索」**に再定義すること。一覧と詳細の画面往復をなくすため、カードクリックで左右ペイン分割（左: 一覧維持、右: 詳細表示）するマスター・ディテール構成を導入する。

### 1.2 ユーザーストーリー

- 「次に遊ぶシナリオを探すとき、候補を次々に見比べたい。一覧⇔詳細の往復で検索条件やスクロール位置を失いたくない」
- 「ホームを開いたら、次回セッションや新着シナリオなど"今の自分に関係ある情報"が一目で分かってほしい」
- 「TRPGを遊ぶ時間の中で使うアプリなので、柔らかく親しみやすい見た目であってほしい」

### 1.3 決定事項（ユーザー確認済み）

| 項目 | 決定 |
|------|------|
| カラー方針 | モックのパステル緑基調へ**全面刷新**（WCAG AAコントラスト対策込み） |
| ナビゲーション | デスクトップは**左サイドバー**に刷新。モバイルは現行BottomNavを維持 |
| 分割ペインのURL | **ルートで表現**（Intercepting/Parallel Routes）。`/scenarios/[id]` のURLを持ちつつ一覧を保持 |
| スコープ | モックの**全要素を要件化**（未実装機能含む）。実装は既存機能で実現可能なものから段階適用 |
| 検索条件 | **現行の条件項目を維持**（モックにある「カテゴリ」等は追加しない） |

## 2. デザイン軸（アプリ全体のデザイン原則）

現行コンセプト「モダン × ソフト × レイヤードUI」を継承しつつ、以下を追加・強化する。

| # | 原則 | 説明 |
|---|------|------|
| 1 | パステルグリーン基調 | 淡く明るい緑を全体の基調色とし、優しく遊び心のあるトーンにする |
| 2 | ボーダーレス・レイヤード | 境界線は原則使わず、面（背景色差）と影で階層を表現（現行踏襲） |
| 3 | 探索ファースト | 一覧⇔詳細の往復を排除。コンテキスト（検索条件・スクロール位置）を失わせない |
| 4 | ダッシュボード型ホーム | ホームは「次のアクション」が見えるパーソナライズドダッシュボード |
| 5 | カバー画像主役 | シナリオのカバー画像を視覚的主役とし、雰囲気でシナリオを選べるようにする |
| 6 | 常設ナビ + 常設CTA | サイドバーに主要ナビと「シナリオ登録」CTAを常設し、どこからでも1クリック |
| 7 | アクセシビリティ非妥協 | パステル化してもWCAG 2.1 AAを維持。文字を載せる面は濃色を使う |

## 3. カラーパレット刷新

### 3.1 方針

- プライマリを現行 `#059568`（濃いブランドグリーン）から**パステル寄りの明るい緑**へ再定義する
- パステル色（明度が高い緑）は**白文字を載せない**。文字を載せる場合は濃緑テキスト、またはボタン面のみ600以深を使う
- グレースケールは現行（blue-gray tint）を維持。緑味への微調整は実装フェーズで必要が出た場合のみ
- アクセント（orange / red / purple / info）は現行の色相を維持し、`50`/`100` の淡色面を積極的に使ってパステルトーンに馴染ませる

### 3.2 新プライマリスケール（暫定値・実装時にPencil/実機で微調整）

```typescript
primary: {
  50:  '#F2F9F4',  // ページ背景に近い最淡
  100: '#E3F3E8',  // チップ選択時、サイドバーのアクティブ状態背景
  200: '#C8E6D2',  // バッジ背景、ホバー面
  300: '#A5D4B6',  // 装飾面、イラスト的アクセント
  400: '#7FBF98',  // アイコン、装飾
  500: '#5FAA7F',  // ★ブランド基調色（バッジ面・アクセント面用。白文字禁止）
  600: '#347A55',  // ★アクションカラー（ボタン等、白文字でAA 4.5:1以上を確保）
  700: '#2A6346',  // ホバー・アクティブ
  800: '#1F4A35',  // パステル面上のテキスト
  900: '#163627',  // 強調テキスト
}
```

### 3.3 背景・サーフェス

```typescript
bg: {
  page: '#F4F7F2',     // ページ背景（現行 #f6f8f7 より緑味を強める）
  card: '#FFFFFF',     // カード背景（現行維持）
  sidebar: '#FBFCFA',  // サイドバー背景（カードよりわずかに沈める or 白 + 影）
  input: '#EDF0EC',    // 入力フィールド（緑味のあるグレーへ寄せる）
}
```

### 3.4 コントラスト規約（必須）

| 組み合わせ | 可否 |
|-----------|------|
| `primary.600`以深 + 白文字 | ○（ボタン、CTAはこれのみ） |
| `primary.50〜200` + `primary.800/900` 文字 | ○（チップ、バッジ、アクティブ状態） |
| `primary.300〜500` + 白文字 | **禁止**（AA未達） |
| `primary.300〜500` 単体 | 装飾・アイコン・画像上バッジ等、3:1を満たすUI部品のみ |

## 4. ナビゲーション構造

### 4.1 デスクトップ: 左サイドバー（常設）

```
┌──────────────┬────────────────────────────┐
│ ロゴ + アプリ名 │                            │
│              │                            │
│ ナビゲーション  │        メインコンテンツ        │
│  ホーム        │                            │
│  シナリオ      │                            │
│  セッション    │                            │
│  スケジュール  │                            │
│              │                            │
│ [+ シナリオ登録]│                            │
│ ユーザー情報   │                            │
└──────────────┴────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| 幅 | 展開時 240px / 折りたたみ時 64px（アイコンのみ）。トグルで切替 |
| 背景 | `bg.sidebar` + `panel` 影（ボーダーレス） |
| ナビ項目 | アイコン + ラベル。ホーム / シナリオ / セッション / スケジュール（既存ルートに対応） |
| アクティブ状態 | `primary.100` 背景の角丸ピル + `primary.800` テキスト・アイコン |
| 非アクティブ | `gray.600`、ホバーで `gray.100` 背景 |
| CTA | 下部に「+ シナリオ登録」プライマリボタン（`primary.600`、常設） |
| ユーザー | 最下部にアバター + ニックネーム。クリックでマイページ/ログアウトのメニュー |
| 未認証時 | CTAの代わりに「ログイン」ボタン |

### 4.2 既存コンポーネントの扱い

| 現行 | 刷新後 |
|------|--------|
| `GlobalHeader`（トップヘッダー） | デスクトップでは廃止し、サイドバーに統合。モバイルでは簡素なトップバー（ロゴ + 検索/通知アイコン）として維持 |
| `BottomNav`（モバイル） | 維持（配色のみ新パレットへ） |
| `SpeedDialFAB` | モバイルでは維持。デスクトップではサイドバーCTAがあるため表示しない |
| `SimpleFooter` | サイドバーレイアウト内のメインカラム下部に維持 |

### 4.3 レスポンシブ分岐

| ブレークポイント | ナビ | 備考 |
|----------------|------|------|
| `lg` 以上 | サイドバー展開 | |
| `md`〜`lg` | サイドバー折りたたみ（アイコンのみ） | |
| `md` 未満 | サイドバー非表示、トップバー + BottomNav | 現行モバイル体験を踏襲 |

## 5. シナリオ一覧 + 詳細分割ビュー（最重要画面）

### 5.1 レイアウト

```
未選択時:                          選択時:
┌─────────────────────┐          ┌──────────┬──────────┐
│ 検索パネル            │          │ 検索パネル │  詳細ペイン │
├─────────────────────┤          ├──────────┤  (右)     │
│ カードグリッド (3-4列) │          │ カード     │  ヒーロー画像│
│                     │          │ グリッド   │  タイトル   │
│                     │          │ (2列)     │  概要 ...  │
└─────────────────────┘          └──────────┴──────────┘
```

| 項目 | 仕様 |
|------|------|
| 分割比率 | 左 55% : 右 45% 目安（右ペインは `minmax(400px, 45%)`） |
| 未選択時 | 一覧をフル幅表示（現行同様） |
| 選択時 | 左ペインのグリッドが列数を減らして縮む（4列→2列等）。アニメーションでペインがスライドイン |
| 選択カード | `primary.100` 背景 or `primary.500` リングで選択状態を明示 |
| スクロール | 左右ペインは**独立スクロール** |

### 5.2 URL・ルーティング（Intercepting/Parallel Routes）

| 操作 | 挙動 |
|------|------|
| カードクリック | `/scenarios/[id]` へソフトナビゲーション。Intercepting Routeにより一覧を保持したまま右ペインに詳細を表示 |
| ブラウザ戻る | 右ペインが閉じて `/scenarios`（検索条件クエリ維持）に戻る |
| URL直接アクセス / リロード | `/scenarios/[id]` は**単独のフル詳細ページ**として表示（現行詳細ページを刷新したもの） |
| 右ペインの「閉じる」ボタン | `router.back()` 相当でペインを閉じる |
| 右ペインの「ページで開く」 | フル詳細ページへハードナビゲーション |
| モバイル（`md`未満） | 分割せず、通常遷移でフル詳細ページへ |

実装方式: `src/app/(main)/scenarios/` 配下に `@detail` Parallel Route + `(.)　[id]` Intercepting Route を設置。検索条件クエリ（nuqs）は遷移後も維持する。

### 5.3 検索パネル

**検索条件は現行項目を完全踏襲**（カテゴリ等のモック独自項目は追加しない）。

| 区分 | 項目 | UI |
|------|------|-----|
| 基本（常時表示） | フリーワード `q` | テキスト入力 |
| 基本（常時表示） | システム `systems` | 複数選択（Select/Combobox） |
| 基本（常時表示） | プレイ人数 `minPlayer`/`maxPlayer` | 範囲入力 |
| 基本（常時表示） | プレイ時間 `minPlaytime`/`maxPlaytime` | 範囲入力 |
| 詳細（展開式） | タグ `tags` | チップ複数選択 |
| 結果ヘッダー | 並び替え `sort` | Select（newest / oldest / playtime_asc / playtime_desc） |

- 「詳細フィルター」はアコーディオン展開（モック準拠）。展開トリガーには適用中の件数バッジを表示
- 適用中の条件はパネル下部にチップ列で表示し、個別解除可能
- 検索パネルは白カード（`card.default` 影、16px角丸）として面で区切る

### 5.4 シナリオカード

| 要素 | 仕様 |
|------|------|
| カバー画像 | 上部に16:9。未設定時はシステム別のプレースホルダー |
| システムバッジ | 画像左上にオーバーレイ配置（`primary.500` 等の塗り + 白文字は画像上のため3:1以上を確認） |
| タイトル | `gray.800`、2行まで |
| メタ情報 | 人数・時間をアイコン付きチップで表示 |
| 評価 | 星表示（`orange.400`） |
| 面・影 | 白背景、`card.default` 影、16px角丸、ホバーで `card.hover` + `translateY(-2px)`（現行踏襲） |

### 5.5 詳細ペイン / フル詳細ページの構成

両者は同一コンポーネント群を共有する（ペインは1カラム縦積み、フルページは余裕があれば2カラム）。

| 順 | セクション | 既存コンポーネント対応 |
|----|-----------|----------------------|
| 1 | ヒーロー（カバー画像 + システムバッジ + タイトル + 評価） | `ScenarioHeader` 刷新 |
| 2 | メタ情報チップ列（人数 / 時間 / 傾向） + アクション（お気に入り・共有・編集） | `ScenarioHeader` 刷新 |
| 3 | シナリオ概要 | `ScenarioInfo` 刷新 |
| 4 | 基本情報テーブル（キー: `gray.500` / 値: `gray.700` の2列、`<hr>`区切り） | `ScenarioInfo` 刷新 |
| 5 | タグ（チップ列） | `ScenarioInfo` 刷新 |
| 6 | セッション情報（このシナリオの履歴・募集） | `SessionSection` |
| 7 | プレイ動画（サムネイルカード横並び） | `VideoSection` |
| 8 | コメント / レビュー | `ReviewSection` |

## 6. ホーム（ダッシュボード）

### 6.1 構成（モック準拠）

```
┌──────────────────────────────────────────┐
│ あいさつ「おかえりなさい、{nickname}さん！」     │
├───────────────────────────┬──────────────┤
│ 次回のセッション（大カード）     │ 通知リスト     │
├───────────────────────────┴──────────────┤
│ 募集中のセッション（横並びカード × 4）           │
├──────────────────┬───────────┬───────────┤
│ 新着シナリオ        │ 人気シナリオ │ 最近のプレイ │
└──────────────────┴───────────┴───────────┘
```

| セクション | 内容 | 実装状況 | フェーズ |
|-----------|------|---------|---------|
| あいさつヘッダー | 時間帯/状況に応じた一言 + ユーザー名 | `HeroSection` あり（刷新） | P3 |
| 次回のセッション | 直近の参加予定セッションの大カード（カバー画像、日時バッジ、システム、参加者、詳細ボタン） | `UpcomingSessions` あり（刷新） | P3 |
| 通知 | 参加申請・承認・コメント等の通知リスト + 「すべて見る」 | **未実装** | P4 |
| 募集中のセッション | 募集中セッションの横並びカード | **未実装**（一覧はあり） | P4 |
| 新着シナリオ | 新着のカード列 + 「すべて見る」 | `NewScenarios` あり（刷新） | P3 |
| 人気シナリオ | ランキング形式リスト（順位 + サムネ + タイトル + 評価） | **未実装** | P4 |
| 最近のプレイ / アクティビティ | 自分の最近のセッション・レビュー | `ActivityTimeline` あり（刷新） | P3 |

- 各セクションは白カードの「面」として区切り、セクションタイトル + 「すべて見る」リンクを統一フォーマットにする
- 未認証時: あいさつ・通知・次回セッションを非表示にし、新着/人気シナリオ + サービス紹介を表示

## 7. コンポーネント共通パターン（新デザイン軸での更新）

| コンポーネント | 仕様 |
|--------------|------|
| カード | 白背景 / `card.default` 影 / 16px角丸 / border禁止（現行踏襲） |
| チップ（非選択） | `gray.100` 背景 + `gray.600` 文字 |
| チップ（選択） | `primary.100` 背景 + `primary.800` 文字 |
| バッジ（システム名等） | `primary.100`〜`200` 背景 + `primary.800` 文字。画像上は塗りバッジ可（コントラスト3:1確認） |
| ボタン Primary | `primary.600` 背景 + 白文字、ホバー `primary.700` |
| ボタン Secondary | 白背景 + `gray.700` 文字 + `secondary` 影（ボーダーは廃止方向で実装時に検証） |
| 入力フィールド | ボーダーなし / `bg.input` 背景 / フォーカスで `primary.600` リング2px |
| 日付バッジ（開催予定等） | `orange.100` 背景 + `orange.800` 文字 等、アクセントの淡色面 + 濃色文字 |
| 区切り | `<hr>` 要素（現行踏襲） |
| 星評価 | `orange.400` |

## 8. 対象画面と実装フェーズ（段階適用）

### 8.1 対象画面（全画面に本デザイン軸を適用する）

| 画面 | ルート | リデザイン内容 |
|------|--------|---------------|
| シナリオ一覧+詳細 | `/scenarios`, `/scenarios/[id]` | 分割ペイン化 + 検索パネル・カード・詳細刷新（5章） |
| ホーム | `/home` | ダッシュボード刷新（6章） |
| セッション一覧/詳細 | `/sessions`, `/sessions/[id]` | 一覧カード・詳細セクションを7章の共通パターンへ。シナリオ一覧と同一のカード/検索スタイル |
| セッション作成 | `/sessions/new` | フォームを新トークン・入力フィールドパターンへ |
| スケジュール | `/schedules` | カレンダー/リストを新トークンへ。日付バッジはアクセント淡色面 |
| ユーザー一覧/詳細 | `/users`, `/users/[id]` | カードリスト・プロフィール表示を共通パターンへ |
| プロフィール | `/profile` | フォーム・セクション面の刷新 |
| シナリオ登録/インポート | `/scenarios/new`, `/scenarios/import` | フォーム刷新 |
| フィードバック | `/feedback`, `/feedback/[id]` | リスト・詳細・コメントUIを共通パターンへ |
| ランディング | `/`（ルート） | 新パレットへの追従（トークン刷新でほぼ自動追従。ヒーロー・CTAの色面確認） |
| ログイン | `/(auth)` | 新パレットへの追従 |

**方針**: トークン・レシピ（Button/Card/Chip等）がsemantic参照で統一されているため、P1のトークン刷新で全画面のベースカラーは自動追従する。各画面フェーズでは「レイアウト・面の構成・セクションフォーマット（タイトル+すべて見る等）」をデザイン軸に揃える作業を行う。

### 8.2 実装フェーズ

| フェーズ | 内容 | 依存 |
|---------|------|------|
| **P1** | デザイントークン刷新（`colors.ts` / `semanticTokens.ts`）+ 左サイドバー導入 + レイアウト再構成（全画面共通基盤） | なし |
| **P2** | シナリオ一覧/詳細の分割ペイン化（Intercepting/Parallel Routes）+ 検索パネル・カード・詳細セクションの刷新 | P1 |
| **P3** | ホーム刷新（既存機能: あいさつ / 次回セッション / 新着シナリオ / アクティビティ） | P1 |
| **P4** | セッション系刷新（一覧/詳細/作成）。一覧はシナリオ一覧と同一のカード・フィルターパターンを共有 | P2 |
| **P5** | スケジュール / ユーザー一覧・詳細 / プロフィールの刷新 | P1 |
| **P6** | フォーム系（シナリオ登録/インポート）+ フィードバック + ランディング/ログインの追従確認 | P1 |
| **P7** | 未実装機能のUI（通知 / 募集中セッション一覧 / 人気シナリオランキング）※機能実装と合わせて別途要件定義 | P3 + 各機能実装 |

各フェーズは `Plan` エージェントで実装計画を作成してから着手する（3ファイル以上・100行以上の変更に該当）。

## 9. 非機能要件

- **アクセシビリティ**: WCAG 2.1 AA維持。3.4節のコントラスト規約を全コンポーネントに適用
- **キーボード操作**: 分割ペインは `Escape` で閉じる。一覧は矢印キーでカード間フォーカス移動（将来対応可）
- **パフォーマンス**: 右ペインの詳細表示はソフトナビゲーションで一覧の再フェッチを発生させない
- **既存テスト**: 検索条件のスキーマ・パーサー（`searchParams.ts` / `schema.ts`）は変更しないため既存テストを維持
