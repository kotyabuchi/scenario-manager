# シナリオ・セッション画面リデザイン要件定義

## 1. 全体方針

対象は Next.js 製 TRPG シナリオ・セッション管理 Web アプリ。

デザインテーマは「TRPGを遊ぶ中で、使いやすい・使いたいと思える管理アプリ」。
全体のカラーリングはパステル系。メインテーマカラーは淡く明るい緑。
雰囲気は柔らかいが、情報の可読性と操作の迷いにくさを最優先する。

UIの一貫性は、レイアウトを全画面で揃えることではなく、以下で担保する。

* 左サイドバー
* カードデザイン
* タグ表示
* フィルターUI
* セクションカード
* 淡い緑を中心にした状態表示
* 余白・角丸・影のトーン

シナリオとセッションは利用目的が違うため、画面構造は無理に統一しない。

---

## 2. 共通レイアウト

### 2.1 サイドバー

全主要画面で左固定サイドバーを使用する。

項目例:

* ホーム
* シナリオ
* セッション
* マイリスト
* お気に入り
* プレイ履歴
* 設定
* 下部にログインユーザー表示

サイドバー下部に主要作成導線を置く。

シナリオ系画面:

* 「＋ シナリオを登録」

セッション系画面:

* 「＋ セッションを作成」

### 2.2 カラー

* 背景: 白〜ごく薄いグリーン
* メインカラー: 淡く明るい緑
* アクションボタン: やや濃い緑
* 成功/参加予定: 緑
* 募集中: ピンクまたは淡い赤系
* 締切間近: オレンジ
* 終了済み: グレー
* タグ: 淡い色のピル型

### 2.3 表示切替

レスポンシブ差分は原則 CSS で制御する。

軽い表示差分:

```tsx
<DesktopOnly />
<MobileOnly />
```

のように CSS の `display: none` / `block` で切り替えてよい。

ただし以下は条件付きマウントにする。

* Drawer の中身
* 重いリスト
* 副作用を持つコンポーネント
* クライアント処理が重い UI

# 3. シナリオ一覧画面

## 3.1 目的

ユーザーが複数の TRPG シナリオを検索・比較し、気になるシナリオを選べる画面。

シナリオ一覧は「探す・比較する」用途が強いため、PCではシナリオ詳細との2ペイン表示を許容する。

## 3.2 URL

```txt
/scenarios
/scenarios/[scenarioId]
```

PCでは `/scenarios/[scenarioId]` で一覧と詳細を同時表示してよい。
モバイルでは詳細ページ単独表示にする。

## 3.3 フィルター

### 基本検索条件

常時表示する。

* フリーキーワード
* システム
* カテゴリ

### 詳細検索条件

展開式にする。

* プレイ時間
* 人数
* HO公開
* タグ

### 検索結果行

フィルターの下に以下を同一行で表示する。

左:

* 検索結果件数

右:

* 並び順
* 表示形式

例:

```txt
検索結果：128件                         並び順：[おすすめ順 ▼] 表示：[カード][リスト]
```

## 3.4 シナリオカード

カード式表示を基本とする。

表示項目:

* サムネイル
* シナリオ名
* TRPGシステム
* カテゴリ
* タグ
* プレイ人数
* プレイ時間
* お気に入り数
* 概要短文
* 追加日または更新日

カード上のシステム表示は、画像に軽く食い込むノッチ風デザインでもよい。

# 4. シナリオ詳細画面

## 4.1 目的

シナリオの内容を確認し、関連セッション・動画・コメント・資料へ移動できる画面。

## 4.2 表示方針

シナリオ詳細はシナリオ情報が主役。
セッション・動画・コメントは関連情報として表示する。

## 4.3 セクション

* ヘッダー

  * サムネイル
  * シナリオ名
  * システム
  * カテゴリ
  * タグ
  * プレイ人数
  * プレイ時間
  * ロスト率
  * 公開範囲
  * 難易度
  * お気に入りボタン
  * セッション作成ボタン

* シナリオ概要

* シナリオ情報

* HO情報

* 関連セッション

* プレイ動画

* コメント

* 外部リンク・資料

## 4.4 タブは禁止

概要 / セッション / 動画 / コメント のようなタブ表示は使わない。
全セクションを縦に並べる場合、タブに見える UI は認知齟齬を生むため禁止。

代わりにページ内ナビを使う。

### PC

画面幅に余裕がある場合、右側に固定の目次を表示する。

### タブレット以下

上部固定の横スクロール目次、または FloatingButton + Drawer で目次を表示する。

### モバイル

FloatingButton から Drawer を開き、表示中セクション一覧を選べるようにする。

# 5. セッション一覧画面

## 5.1 目的

ユーザーが参加可能なセッション、参加予定のセッション、終了済みセッションを探せる画面。

シナリオ一覧と違い、セッションは「比較」より「参加判断」が主目的。
そのため、一覧と詳細の2ペイン表示は使わない。

## 5.2 URL

```txt
/sessions
```

## 5.3 レイアウト

1画面全体を使ったカードグリッド表示にする。
「詳細ペインの左側だけを切り取ったような横長リスト」は避ける。

PCでは3カラム程度のカードグリッドを基本とする。
タブレットでは2カラム、スマホでは1カラム。

## 5.4 フィルター

基本フィルター:

* キーワード
* システム
* 募集状況
* プレイ日時
* タグ

追加フラグ:

* 参加予定のみ表示
* 終了済みも表示

この2つは検索条件として扱う。

## 5.5 検索結果行

フィルターの下に表示する。

左:

* 検索結果件数

右:

* 並び順
* 表示形式

## 5.6 セッションカード

カードは募集カードとして設計する。

表示項目:

* サムネイル
* セッション名
* シナリオ名
* システム
* タグ
* GM名
* 開催日時
* 募集状況
* 現在人数 / 募集人数
* 残り人数
* 参加予定バッジ
* 終了済み表示
* ブックマーク

### 参加予定

参加予定のセッションにはカード上部に緑系バッジを表示する。

例:

```txt
参加予定
```

### 終了済み

終了済みセッションはグレーアウトする。

具体例:

* 画像の彩度を落とす
* カード全体の背景を薄いグレーにする
* ステータスバッジを「終了済み」にする
* アクション色を弱める

終了済みでも内容は読めるようにし、完全に無効化しない。

# 6. セッション詳細画面

## 6.1 目的

セッションへの参加判断、参加後の準備、終了後の振り返りを行う画面。

セッション詳細は1つの URL に統一する。
ユーザー状態に応じて表示ブロックを変える。

## 6.2 URL

```txt
/sessions/[sessionId]
```

募集一覧から遷移しても、自分の参加セッション一覧から遷移しても、同じ URL を使う。

## 6.3 表示モード

表示モードはユーザーとセッションの関係で決まる。

* 未ログイン
* 未参加
* 申請中
* 参加確定
* GM
* 管理者
* 終了後

ページを分けるのではなく、返却する ViewModel のブロックを変える。

## 6.4 ViewModel 方針

サーバー側で権限判定し、表示可能なブロックだけ返す。

例:

```ts
type SessionDetailViewModel = {
  viewer: {
    role: "guest" | "applicant" | "participant" | "gm" | "admin"
    applicationStatus?: "pending" | "approved" | "rejected"
  }

  public: PublicSessionBlock

  participant?: ParticipantSessionBlock

  gm?: GmSessionBlock
}
```

画面側では block が存在する場合のみ表示する。

```tsx
<PublicSection data={data.public} />

{data.participant && (
  <ParticipantSection data={data.participant} />
)}

{data.gm && (
  <GmSection data={data.gm} />
)}
```

ただし、クライアント側の非表示はセキュリティではない。
参加者限定情報やGM限定情報はサーバー側で返さないこと。

## 6.5 データ取得

`page.tsx` からサーバー関数を呼び、ViewModel を生成する。

読み取り処理は server-only query 関数でも Server Action でも実装可能。
ただし、実装上は query / mutation を分ける方が望ましい。

推奨構成:

```txt
features/session/server/
  get-session-detail-view-model.ts
  get-session-list.ts

features/session/actions/
  apply-session.ts
  approve-participant.ts
  reject-participant.ts
  update-session.ts
  post-comment.ts
```

## 6.6 セッション詳細の構成

### ヘッダー

表示項目:

* パンくず
* サムネイル
* 募集状態バッジ
* セッション名
* システム
* タグ
* 概要短文
* プレイ人数
* プレイ時間
* ロスト率
* 募集状況
* GM名
* 作成日
* お気に入り
* シェア
* メニュー

主要アクション:

* 参加申請を送る
* GMにメッセージを送る

申請後は状態メッセージを出す。

例:

```txt
GMの承認後、参加が確定します。
```

### 公開セクション

未参加でも表示できる。

* 概要
* 募集要項
* 日程・時間
* 参加者
* コメント
* 関連リンク・資料

### 参加者限定セクション

参加確定後のみ表示。

* Discordリンク
* ココフォリアURL
* HO情報
* キャラクターシート
* 共有資料
* GMからの連絡
* 参加者用メモ

### GM限定セクション

GMまたは管理者のみ表示。

* 参加申請一覧
* 承認 / 却下
* 募集設定
* 参加者管理
* GMメモ
* セッション編集導線

### 終了後セクション

終了済みの場合に表示。

* プレイ記録
* 感想
* レビュー導線
* プレイ動画
* ログ
* アーカイブ資料

## 6.7 タブは禁止

セッション詳細でもタブは使わない。

概要、募集要項、日程、参加者、コメントなどが全部縦に存在する場合、タブに見える UI は使わない。

代わりに目次を使う。

### PC

右側に固定の目次。

### 横幅が狭い画面

FloatingButton で目次 Drawer を開けるようにする。

目次は実際に表示されているセクションだけを表示する。

例:

```ts
const sections = [
  publicOverview && { id: "overview", label: "概要" },
  requirements && { id: "requirements", label: "募集要項" },
  schedule && { id: "schedule", label: "日程・時間" },
  participants && { id: "participants", label: "参加者" },
  participantLinks && { id: "links", label: "参加者用リンク" },
  gmPanel && { id: "gm", label: "GM管理" },
  comments && { id: "comments", label: "コメント" },
].filter(Boolean)
```

# 7. 置き換え実装の優先順

## Phase 1: セッション一覧

最初に `/sessions` をリデザインする。

理由:

* 2ペインをやめる方針が明確
* カードグリッド化の影響範囲が比較的限定的
* 参加予定 / 終了済みフラグの仕様が固まっている

実装内容:

* フィルター再設計
* 参加予定のみ表示フラグ
* 終了済みも表示フラグ
* セッションカードグリッド
* 終了済みグレーアウト
* 参加予定バッジ

## Phase 2: セッション詳細

次に `/sessions/[sessionId]` をリデザインする。

実装内容:

* タブ削除
* セクション縦並び化
* 右サイド目次
* FloatingButton + Drawer 目次
* public / participant / gm block の ViewModel 化
* 表示権限制御

## Phase 3: シナリオ一覧

シナリオ一覧は既存の2ペイン方針を維持しつつ、フィルター仕様を整理する。

実装内容:

* 基本フィルター3項目
* 詳細フィルター4項目
* 検索結果行に並び順・表示形式を配置
* カード表示の調整

## Phase 4: シナリオ詳細

最後にシナリオ詳細を整理する。

実装内容:

* タブ削除
* セクション縦並び化
* 目次導入
* 関連セッション / 動画 / コメントのセクション整理

---

# 8. 禁止事項

以下は避ける。

* セッション一覧と詳細を2ペインにする
* セッション一覧を横長リストだけにする
* 全セクションが縦に並んでいるのにタブUIを使う
* 参加者限定情報をクライアント側非表示だけで隠す
* シナリオとセッションを無理に同じレイアウトに揃える
* 終了済みセッションを完全に操作不能・読解不能にする
* モバイルで目次にアクセスできない状態にする

---

# 9. 完了条件

## セッション一覧

* 2ペインではない
* カードグリッドで表示される
* 参加予定のみ表示フラグがある
* 終了済みも表示フラグがある
* 参加予定バッジが表示される
* 終了済みがグレーアウトされる
* 検索結果件数、並び順、表示形式が適切に配置されている

## セッション詳細

* タブUIが存在しない
* セクションが縦に並んでいる
* PCで目次が表示される
* 狭い画面でも目次を開ける
* 表示されているセクションだけが目次に出る
* public / participant / gm の権限別ブロックがサーバー側で制御されている

## シナリオ一覧

* 基本検索条件がフリーキーワード、システム、カテゴリ
* 詳細検索条件がプレイ時間、人数、HO公開、タグ
* 検索結果件数と同じ行右端に並び順・表示形式がある
* カード式表示が維持されている

## シナリオ詳細

* タブUIが存在しない
* 各関連情報がセクションとして縦に表示される
* 目次で各セクションへ移動できる
