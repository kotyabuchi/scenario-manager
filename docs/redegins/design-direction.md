# デザイン刷新 方針ドキュメント

> モック（ChatGPT Image 2）と簡易要件（`requirements.md`）から「全体的なトーン」と「レイアウト」を抽出し、本プロジェクトの既存デザインシステムへ落とし込んだ方針書。
> 実装計画は `docs/plans/ui-redesign-scenarios.md` を参照。

## 0. 結論サマリ

- **トーンは“ほぼ現状維持で正しい”**。モックのトーン（淡い緑みの白背景・ボーダーレス・ソフトシャドウ・角丸）は既存 `semanticTokens.ts` / `ui-design-system` メモリと一致しており、刷新の本体は**情報レイアウト**にある。
- **本丸は2点**:
  1. PC のグローバルナビを**左 `SideMenu`** 化（モバイルは現状 BottomNav + SpeedDialFAB を維持）＝ハイブリッド。
  2. シナリオ**一覧と詳細の左右2ペイン**（PC同時表示 / モバイル単独表示）。
- **モック・ChatGPT要件は鵜呑みにしない**。下記「不採用・読み替え」を明示する。

## 1. モックから抽出したトーン（と既存との対応）

| 観点 | モックの表現 | 既存トークン | 対応 |
|------|------------|-------------|------|
| 背景 | 淡い緑みの白 | `bg.page` (`#f6f8f7`) | そのまま |
| 面 | 白カード・境界線なし・影で浮かせる | `card.default` / `card.hover` | そのまま |
| 角丸 | カード16px / チップ12px | `2xl` / `xl` | そのまま |
| プライマリ | 淡く明るい緑、CTAはやや濃い緑 | `primary.500` → hover `600` | そのまま |
| システム名ノッチ | サムネ左上に食い込む白ラベル | `cardSystemLabel`（CSS mask 逆角丸） | **実装済み** |
| 状態色 | 参加予定=緑 / 募集中=ピンク淡赤 / 締切間近=オレンジ / 終了=グレー | `badge.success/warning/neutral` | **「募集中=ピンク」専用が未定義** → 追加 |
| タグ | 淡い色のピル | `chip.label*`（グレー単色） | **カテゴリ別カラー未定義** → 追加検討 |

### トークン追加（最小）
- `badge.recruiting.*`（募集中 / ピンク〜淡赤系）… 「募集中」を `warning`(オレンジ=締切間近) と色で区別するため。
- `sideMenu.*`（背景・アクティブ/非アクティブ項目・幅）。
- （任意）タグのカテゴリ別カラー `tag.{closed,setting,genre,style,warning,default}.*`。視覚情報量を上げる施策。**配色は実装時に Pencil/MCP で確定**（未決定事項）。

> 既存トークンで賄える色をハードコードしないこと（`styling-rules.md`）。新色は必ず `semanticTokens.ts` に定義してから参照する。

### ボーダーの扱い（要件「完全ボーダーレス」の上書き）

ChatGPT 要件の「完全ボーダーレス」は採用しない。本プロジェクトは **「ボーダーレスを基調とし、border は“影で表現できない時の意図的な道具”として限定許可」** とする。

判断基準は **elevation の意味**で決める: **浮かせたい＝影 / 同じ高さで区切りたい＝border**。

| border を使う（最適な場面） | border を使わない（従来どおり影） |
|---|---|
| フォーカスリング（既存 `borders.focusRing`） | カードの輪郭（`card.default` 影） |
| 入力欄のアフォーダンスが必要な箇所 | 浮かせたい面（パネル/メニュー/ダイアログ） |
| 高密度な表・リスト行の区切り（影だと重い） | チップ/タグの外形 |
| 同一 elevation の面どうしの境界 | ホバーで持ち上がる要素 |
| 半透明背景・画像上の要素の輪郭（影が効かない） | |
| 選択/アクティブ状態の強調（例: 選択カードに `primary` border） | |

- border は必ず既存トークン（`border.{default,subtle,focus,error}` / `borders.soft`(=`1px solid gray.100`)）を参照する。`1px solid #...` のハードコードはしない。
- **注記**: 本方針に合わせ `styling-rules.md` と Serena `ui-design-system` メモリも「基調ボーダーレス＋限定許可」に更新済み（カードの輪郭は対象外で従来どおり影で表現）。

## 2. レイアウトシステム

### 2.1 グローバル構造（ハイブリッド）

```
PC (lg+):
┌───────────┬────────────────────────────────────────────┐
│           │  page content                              │
│ SideMenu  │  （/scenarios/[id] では 一覧 | 詳細 の2ペイン） │
│ (240px)   │                                            │
│ sticky    │                                            │
└───────────┴────────────────────────────────────────────┘

モバイル (base):
┌────────────────────────────────────────────┐
│ GlobalHeader（簡易・必要なら）               │
│ page content（1カラム）                      │
│ BottomNav + SpeedDialFAB（現状維持）         │
└────────────────────────────────────────────┘
```

- **`SideMenu`**: ロゴ＋ナビ＋下部に作成CTA・設定・ユーザー。`display: { base: 'none', lg: 'flex' }` で**PCのみ**表示。`position: sticky; top: 0; height: 100dvh`。
- **モバイル**: `SideMenu` は出さない。既存 `BottomNav` / `SpeedDialFAB` をそのまま使う。`GlobalHeader` は lg 以上で隠し、モバイルのみ簡易表示（または BottomNav に統合）。
- **命名規約（過去のユーザー指定）**: コンポーネント名は **`SideMenu`**。「サイドバー」「LeftSidebar」は使わない。

### 2.2 シナリオ 2ペイン

| 画面 | URL | PC | モバイル |
|------|-----|----|---------|
| 一覧 | `/scenarios` | 一覧フル幅 | 一覧フル幅 |
| 詳細 | `/scenarios/[id]` | **左:一覧（縮小） / 右:詳細パネル** | 詳細単独ページ |

- **実装方式**: Next.js **Parallel Routes + Intercepting Routes**。
  - 一覧から遷移 → `@detail/(.)[id]` がパネルに描画（一覧の state を保持）。
  - 直接 `/scenarios/[id]` アクセス・リロード → 既存フルページ `[id]/page.tsx` が描画。
  - ブラウザバックでパネルが閉じ、一覧がフル幅へ。
- **フィルターはペイン上部に集約**（インライン）。現状の「左フィルターレール（SearchSidebar）」は廃止。理由: `SideMenu` + 一覧 + 詳細で既に3カラムであり、さらに左レールを足すと破綻する。
- 検索結果行: 左=件数 / 右=並び順・表示形式（カード/リスト）。

### 2.3 詳細は「タブ禁止・目次方式」（要件採用、モック不採用）

- モックは詳細にタブ（概要/セッション/動画/コメント/資料）を描いているが、**要件はタブ禁止**。全セクションを縦に並べ、**目次（TOC）でアンカースクロール**する。
- **タブに見せない**こと（要件の核心 = 認知齟齬の回避）:
  - ✅ 目次 = 全セクションを常時DOMに描画／クリックで該当アンカーへスクロール／現在地をハイライト。
  - ❌ タブ = クリックでコンテンツを差し替え（他は非表示）。
- **目次の出し分け**:
  - PCで**幅に余裕がある場合**は右側固定の目次。
  - **2ペインの詳細パネル（幅≈50%）やタブレット**では幅が足りないため、**上部 sticky の横並び目次** か **FloatingButton + Drawer**。横並び目次はピル/リンク主体にしてタブと誤認させない。
  - モバイルは FloatingButton から Drawer。
- **表示中セクションだけ**を目次に出す（存在しないブロックは項目化しない）。

### 2.4 セッションは2ペインにしない（要件採用）

- セッションは「比較」より「参加判断」が主目的。一覧は**カードグリッド**（PC3 / タブレット2 / スマホ1）。詳細は単一URL `/sessions/[id]` で ViewModel のブロック出し分け。
- 本刷新の**スコープ外（後続フェーズ）**。今回はシナリオ一覧・詳細を優先（ユーザー指定の主目的）。ただしトークン・`SideMenu`・カード/タグ規約はセッションにも波及する共通基盤として設計する。

## 3. コンポーネント方針

| コンポーネント | 方針 |
|---------------|------|
| `SideMenu`（新規） | PCグローバルナビ。ナビ項目は**既存ルート準拠**（ホーム/シナリオ/セッション/スケジュール/ユーザー/マイページ）。モックの「マイリスト/お気に入り/プレイ履歴」は実ルートが揃ってから追加（今回は作らない）。 |
| `ScenarioCard` | 現状ベース＋トーン微修正。ノッチ式システムラベルは維持。タグはカテゴリ別カラー化を検討。 |
| `ScenarioFilters`（新規） | ペイン上部のインラインフィルター。基本3（フリーワード/システム/カテゴリ）＋詳細展開（プレイ時間/人数/HO公開/タグ）。 |
| `ScenarioDetailPanel`（新規） | 2ペイン右側。**タブ不使用・セクション縦並び＋目次**。既存 `ScenarioInfo/SessionSection/VideoSection/ReviewSection` を再利用。 |
| `GlobalHeader` | lg 以上で非表示化（モバイルのみ）。廃止はモバイル動作確認後に判断。 |
| `BottomNav` / `SpeedDialFAB` | 現状維持。 |

## 4. 不採用・読み替え（モック/ChatGPT要件を鵜呑みにしない点）

| 出典 | 内容 | 本方針 |
|------|------|--------|
| モック | ブランド名「シナリオノート」 | **不採用**。既存「シナプレ管理くん」を踏襲。 |
| モック | 詳細のタブUI | **不採用**。要件どおりタブ禁止・目次方式。 |
| モック | サイドバー項目（マイリスト等） | **読み替え**。既存ルートに準拠、未実装ルートは作らない。 |
| 要件 | グローバル全面サイドバー化 | **読み替え**。PCのみ `SideMenu`、モバイルは現状維持（ハイブリッド）。 |
| 要件 | 実装順は「セッション一覧 → 詳細 → シナリオ…」 | **読み替え**。ユーザー主目的に従い**シナリオ2ペインを先行**。セッションは後続。 |
| モック | 表示項目・件数・文言 | 参考に留める（確定仕様ではない）。 |
