# デザイン刷新 方針ドキュメント

> モック（ChatGPT Image 2）と簡易要件（`requirements.md`）から「全体的なトーン」と「レイアウト」を抽出し、本プロジェクトの既存デザインシステムへ落とし込んだ方針書。
> 実装計画は `docs/plans/ui-redesign-scenarios.md` を参照。

## 0. 結論サマリ

- **トーンは“ほぼ現状維持で正しい”**。モックのトーン（淡い緑みの白背景・ソフトシャドウ・角丸）は既存 `semanticTokens.ts` / `ui-design-system` メモリと一致しており、刷新の本体は**情報レイアウト**にある。
- **更新（2026-07 シナリオ詳細実装で確定）**: カード面は「純白＋影のみのボーダーレス」から **「`paper`（淡い緑みの白）背景 ＋ 薄ボーダー（`paperBorder`）＋ ソフト影」のレイヤードカード** に変更。従来の「カードはボーダーレス（影のみ）」方針を上書きする（§1「面」行・§ボーダーの扱い を参照）。
- **本丸は2点**:
  1. PC のグローバルナビを**左 `SideMenu`** 化（モバイルは現状 BottomNav + SpeedDialFAB を維持）＝ハイブリッド。
  2. シナリオ**一覧と詳細の左右2ペイン**（ペイン領域740px以上で同時表示 / 狭い画面では単独表示）。
- **モック・ChatGPT要件は鵜呑みにしない**。下記「不採用・読み替え」を明示する。

### トークン追加（最小）
- `badge.recruiting.*`（募集中 / ピンク〜淡赤系）… 「募集中」を `warning`(オレンジ=締切間近) と色で区別するため。**実装済み**（Badge `variant="recruiting"` → Pill `tone="pink"`）。
- `sideMenu.*`（背景・アクティブ/非アクティブ項目・幅）。**実装済み**。
- `canvas` / `paper` / `paperBorder.{50,100,200}` / `lightGreen.{bg,border}`（カード面のレイヤード表現用）。**実装済み**（下記）。
  - `canvas` `oklch(0.975 0.004 150)` … ページ背景（`bg.page`）。
  - `paper` `oklch(0.988 0.005 120)` … カード面背景（`bg.card`。純白ではなく僅かに緑み）。
  - `paperBorder.{50,100,200}` … カード面用の緑みグレー薄ボーダー（gray と同一 L ランプ・色相のみ緑 H=120）。主カード枠=`50`、内側サブカード/区切り=`100`。
  - `lightGreen.{bg,border}` … ほぼ白の極淡グリーン面（ボックス内側相当）。
- タグは DB の `tags.color` を表示する。カテゴリ別の固定カラートークンは追加しない（§動的タグカラー）。

> 既存トークンで賄える色をハードコードしないこと（`styling-rules.md`）。新色は必ず `semanticTokens.ts` に定義してから参照する。

### ボーダーの扱い（要件「完全ボーダーレス」の上書き）

ChatGPT 要件の「完全ボーダーレス」は採用しない。本プロジェクトは **「ボーダーレスを基調とし、border は“影で表現できない時の意図的な道具”として限定許可」** とする。

判断基準は **elevation の意味**で決める: **浮かせたい＝影 / 同じ高さで区切りたい＝border**。ただしカード面は「影 ＋ 薄ボーダーの併用」を標準とする（下記の更新）。

| border を使う（最適な場面） | border を使わない（従来どおり影のみ） |
|---|---|
| **カード面の輪郭（`paperBorder` 薄ボーダー ＋ `card.default` 影の併用）** | 浮かせたい面（パネル/メニュー/ダイアログ） |
| フォーカスリング（既存 `borders.focusRing`） | チップ/タグの外形 |
| 入力欄のアフォーダンスが必要な箇所 | ホバーで持ち上がる要素 |
| 高密度な表・リスト行の区切り（影だと重い） | |
| 同一 elevation の面どうしの境界 | |
| 半透明背景・画像上の要素の輪郭（影が効かない） | |
| 選択/アクティブ状態の強調（例: 選択カードに `primary` border） | |

- **更新（2026-07）**: 旧方針では「カードの輪郭は border 対象外＝影のみ」だったが、モック実測に合わせ **カード面は `paperBorder` の薄ボーダー ＋ ソフト影を併用** する方式に変更した。ごく薄い緑みグレー枠で面の輪郭を締めつつ、影で浮遊感を残す“レイヤードカード”表現。
- border は必ず既存トークン（カード面=`paperBorder.{50,100,200}` / 汎用=`border.{default,subtle,focus,error}` / `borders.soft`(=`1px solid gray.100`)）を参照する。`1px solid #...` のハードコードはしない。
- **注記**: 本方針に合わせ `styling-rules.md` と Serena `ui-design-system` メモリも更新済み。
- **追従漏れ（要対応）**: 一覧の `ScenarioCard`（`src/app/(main)/scenarios/_components/styles.ts`）は現状まだ「純白＋影のみ・ボーダーなし」で、新方針（`paper` ＋ `paperBorder`）に未追従。詳細パネル（`ScenarioDetailPanel`）は追従済み。一覧カードの移行は別途対応。

### 動的タグカラー（DB管理・OKLCH）

タグの色は**固定配色ではなく DB（`tags.color`）で管理**する（タグは増え続けるため、コード側の「タグ名→色」固定マップを持たない）。

- 保存形式: **基準色を OKLCH 文字列**（例: `oklch(0.65 0.15 350)`）で `tags.color` に保存。
- 表示: 基準色から**同色相で bg（高明度・低彩度）と text（低明度）を導出**し（`src/lib/tagColor.ts`）、コントラストを構造的に担保。`Tag` コンポーネント（`Pill` の `tone="custom"` ラッパー）が **CSS 変数（`--pill-bg` / `--pill-text`）を `style` で注入**して適用。`color` が null/不正ならグレーにフォールバック。
- スコープ: 現状は**表示のみ**（色設定UI・ピッカーは未対応）。

**規約の例外（データ駆動の動的色に限る）**:

| 通常の規約 | 動的タグ色での例外 | 理由 |
|---|---|---|
| OKLCH 禁止（HEXトークンを使う） | OKLCH を**許可** | 明度を振るだけで a11y 安全な bg/text を生成できる。静的トークンとは別系統 |
| インラインスタイル（style属性）禁止 | CSS 変数注入に限り **`style` を許可** | DB 由来の色はクラス事前生成が不可能。Pill 本体ではなく `Tag` に隔離 |

> 静的な色（ステータスバッジ等）は従来どおり HEX トークン固定。OKLCH/inline-style 例外は**データ駆動の動的色のみ**。

## 2. レイアウトシステム

### 2.1 グローバル構造（ハイブリッド）

```
2ペインの利用可能幅がある画面:
┌───────────┬────────────────────────────────────────────┐
│           │  page content                              │
│ SideMenu  │  （/scenarios/[id] では 一覧 | 詳細 の2ペイン） │
│ (240px)   │                                            │
│ sticky    │                                            │
└───────────┴────────────────────────────────────────────┘

モバイル (base):
┌────────────────────────────────────────────┐
│ GlobalHeader（簡易・必要なら）               │
│ page content（1カラム）                      │
│ BottomNav + SpeedDialFAB（現状維持）         │
└────────────────────────────────────────────┘
```

- **`SideMenu`**: ロゴ＋ナビ＋下部に作成CTA・設定・ユーザー。`display: { base: 'none', lg: 'flex' }` で**PCのみ**表示。`position: sticky; top: 0; height: 100dvh`。
- **モバイル**: `SideMenu` は出さない。既存 `BottomNav` / `SpeedDialFAB` をそのまま使う。`GlobalHeader` は lg 以上で隠し、モバイルのみ簡易表示（または BottomNav に統合）。
- **命名規約（過去のユーザー指定）**: コンポーネント名は **`SideMenu`**。「サイドバー」「LeftSidebar」は使わない。

### 2.2 シナリオ 2ペイン

| 画面 | URL | PC | モバイル |
|------|-----|----|---------|
| 一覧 | `/scenarios` | 一覧フル幅 | 一覧フル幅 |
| 詳細 | `/scenarios/[id]` | ペイン領域740px以上なら**左:一覧 / 右:詳細パネル**（1:1） | 詳細単独ページ |

- **実装方式**: Next.js **Parallel Routes + Intercepting Routes**。
  - 一覧から遷移 → `@detail/(.)[id]` がパネルに描画（一覧の state を保持）。
  - 直接 `/scenarios/[id]` アクセス・リロード → 既存フルページ `[id]/page.tsx` が描画。
  - ブラウザバックでパネルが閉じ、一覧がフル幅へ。
- 一覧の詳細リンクは検索条件と並び順を含む安全な `returnTo` を渡す。パネルの「閉じる」は一覧からの遷移履歴へ戻り、追加読込結果・スクロール・発火元フォーカスも保つ。直URL・リロードで表示される単独ページは `returnTo` があればその一覧へ、なければ `/scenarios` へ戻る。
- **フィルターはペイン上部に集約**（インライン）。現状の「左フィルターレール（SearchSidebar）」は廃止。理由: `SideMenu` + 一覧 + 詳細で既に3カラムであり、さらに左レールを足すと破綻する。
- 検索結果行: 左=件数 / 右=並び順。デザイン刷新MVPではカード表示のみとし、カード／リスト切替は後続へ回す。
- 2ペインは一覧:詳細=1:1、間隔24px。Storybookの展開済み検索ではペイン領域740px（各358px）が表示を保てる下限で、720pxでは結果行が不自然に折り返される。SideMenuと余白を差し引いた利用可能幅で切り替える。

### 2.3 詳細はセクション縦並び、目次は単独ページだけ

- 詳細にはタブを設けず、全セクションを縦に並べる。単独ページでは目次（TOC）でアンカースクロールできるようにし、2ペインの詳細パネルには目次を置かない。
- **タブに見せない**こと（要件の核心 = 認知齟齬の回避）:
  - ✅ 目次 = 全セクションを常時DOMに描画／クリックで該当アンカーへスクロール／現在地をハイライト。
  - ❌ タブ = クリックでコンテンツを差し替え（他は非表示）。
- **目次の出し分け**:
  - 単独ページの広幅では右側固定の目次。
  - 単独ページの狭幅では FloatingButton + Drawer。
  - 2ペインの詳細パネルでは幅にかかわらず非表示。
- **表示中セクションだけ**を目次に出す（存在しないブロックは項目化しない）。

### 2.4 セッションは2ペインにしない（要件採用）

- セッションは「比較」より「参加判断」が主目的。一覧は**カードグリッド**（PC3 / タブレット2 / スマホ1）。詳細は単一URL `/sessions/[id]` で ViewModel のブロック出し分け。
- 本刷新の**スコープ外（後続フェーズ）**。今回はシナリオ一覧・詳細を優先（ユーザー指定の主目的）。ただしトークン・`SideMenu`・カード/タグ規約はセッションにも波及する共通基盤として設計する。

## 3. コンポーネント方針

| コンポーネント | 方針 |
|---------------|------|
| `SideMenu`（新規） | PCグローバルナビ。ナビ項目は**既存ルート準拠**（ホーム/シナリオ/セッション/スケジュール/ユーザー/マイページ）。モックの「マイリスト/お気に入り/プレイ履歴」は実ルートが揃ってから追加（今回は作らない）。 |
| `ScenarioCard` | 現状ベース＋トーン微修正。ノッチ式システムラベルを維持し、タグにはDB色を渡す。 |
| `ScenarioFilters`（新規） | ペイン上部のインラインフィルター。基本はシナリオ名キーワード、詳細展開はシステム/タグ/プレイ人数/プレイ時間。 |
| `ScenarioDetailPanel` | 2ペイン右側と単独ページで共用。タブ・目次を設けず、詳細情報・関連セッション・動画・コメントを縦に表示する。単独ページの目次は別に配置する。 |
| `GlobalHeader` | lg 以上で非表示化（モバイルのみ）。廃止はモバイル動作確認後に判断。 |
| `BottomNav` / `SpeedDialFAB` | 現状維持。 |

## 4. 不採用・読み替え（モック/ChatGPT要件を鵜呑みにしない点）

| 出典 | 内容 | 本方針 |
|------|------|--------|
| モック | ブランド名「シナリオノート」 | **不採用**。既存「シナプレ管理くん」を踏襲。 |
| モック | 詳細のタブUI | **不採用**。セクションを縦に並べ、単独ページだけに目次を置く。 |
| モック | サイドバー項目（マイリスト等） | **読み替え**。既存ルートに準拠、未実装ルートは作らない。 |
| 要件 | グローバル全面サイドバー化 | **読み替え**。PCのみ `SideMenu`、モバイルは現状維持（ハイブリッド）。 |
| 要件 | 実装順は「セッション一覧 → 詳細 → シナリオ…」 | **読み替え**。ユーザー主目的に従い**シナリオ2ペインを先行**。セッションは後続。 |
| モック | 表示項目・件数・文言 | 参考に留める（確定仕様ではない）。 |

## 5. 実装時に確定した事項と後続課題

- 2ペイン切替はビューポート幅1044px。SideMenu 240px、左右余白48px、スクロールバーを含めて各ペイン358px以上を確保する。1043px以下では詳細を単独表示する。
- `GlobalHeader` はモバイルのヘッダーとして残す。
- モックの「マイリスト/お気に入り/プレイ履歴」の新規ルートは別要件として扱う。
