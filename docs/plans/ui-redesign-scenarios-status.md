# シナリオUIリデザインの実装状況

更新日: 2026-09-24。対象ブランチ: `feature/ui-redesign-scenarios`。

シナリオ一覧と詳細は新しい表示部品に接続済み。PCには左サイドメニューを置き、一覧から詳細を開くと利用可能な幅に応じて2ペインまたは詳細単独で表示する。直URLとリロードでは詳細単独ページを表示する。画面設計と採用する検索項目は [実装計画](ui-redesign-scenarios.md) を参照。

## 実装済みの構成

| 領域 | 実装 |
|---|---|
| 共通ナビゲーション | `SideMenu` をPCのメインレイアウトに接続。狭い画面は `GlobalHeader`、`BottomNav`、`SpeedDialFAB` を使用 |
| 一覧 | `ScenarioListPanel` にインライン検索、件数、並び順、カード、追加読込を接続。検索結果は既存APIを使用 |
| 検索 | 基本はシナリオ名キーワード。詳細はシステム、タグ、プレイ人数、プレイ時間。下書きと確定値を分け、確定値をURLに同期 |
| 詳細 | `ScenarioDetailPanel` に共通ViewModelで取得した詳細、関連セッション、動画、コメント、お気に入り操作を渡す。タブは使用しない |
| 目次 | 単独表示でのみ使用。広い画面では右側に固定し、狭い画面ではDrawerから開く。本文と共通のセクションIDを参照 |
| ルーティング | Parallel RoutesとIntercepting Routesを使用。一覧からの遷移では詳細をスロットに描画し、直URL・リロードでは通常の詳細ページを描画 |
| タグ | DBの `tags.color` を `Tag` に渡す。不正値や未設定は既定色にフォールバック |

## レイアウトと復帰

- 2ペインは一覧:詳細を1:1、間隔24pxで配置する。左右ペインの合計幅1000pxを下限とし、左右余白48pxを含むシナリオ領域1072pxで切り替える。SideMenuは240pxから56pxへ折りたためるため、画面全体の固定幅では判定しない。下限未満では詳細を単独表示する。
- PCのスクロールペインはビューポートの高さを使い、内容の上下余白24pxはペイン内に置く。一覧単独表示のスクロールバーはコンテンツ領域の右端に置き、2ペイン時は従来の横余白と1:1の比率を保つ。共通フッターは表示しない。各ペインを絶対配置要素の基準にして内容のはみ出しをペイン内へ閉じ、ページ全体には縦スクロールを作らない。
- 一覧から開いた詳細の「閉じる」または「シナリオ一覧に戻る」は、確定した検索条件と並び順を含む元の一覧URLへ戻る。レイアウトのセッションに検索結果、追加読込位置、一覧スクロール位置、開いたカードを保持するため、一覧の子画面が再マウントされても復元できる。
- 直URL・リロード時の戻り先は詳細URLの `returnTo` を使用する。同一サイトの `/scenarios` と許可済み検索パラメータだけを受け付け、ない場合は `/scenarios` に戻る。リロード後の追加読込分・スクロール位置は永続化しない。
- 詳細を開くと先頭の戻る／閉じるリンクへフォーカスを移し、一覧へ戻ると発火元カードへフォーカスを戻す。
- カード／リスト表示切替は今回のMVPに含めない。

## 検証

- TypeScript型チェック、変更領域のBiome、シナリオ関連Vitest 213件が成功。Booth/TALTO配布元表示を復元する追加テストも成功。
- 当時の本番ビルドでのシナリオ関連Playwright E2EはPC29件・モバイル22件が成功。直URL・リロード、条件付き復帰、追加読込40件・スクロール・フォーカスの保持を確認。幅固定のPC用7件はモバイルプロジェクトで対象外としてスキップ。現在の幅切替は別途1312/1311pxとSideMenu開閉で確認する。
- 認証済みの詳細操作はセットアップを含むPlaywright E2E 7件が成功。
- 共通ナビゲーション、認証済みナビゲーション、スモーク、一覧・詳細ルーティングの回帰テストはPC・モバイル合計36件が成功。幅固定の7件はモバイルで対象外としてスキップ。
- Storybookの本番ビルドとシナリオパネルのブラウザーテスト8件が成功。狭幅の操作ボタン、検索、最小ペイン幅、長文タイトル、保存失敗時の再操作を確認。
- シナリオルーティングのPlaywright E2Eは9件が成功。1360pxでページ全体の縦スクロールなし、左右ペインの独立スクロールを確認。1312/1311pxでの切替と1280pxでのSideMenu開閉による切替も確認。
- E2Eの本番ビルドは `.next-e2e` に分離し、開発サーバーの `.next` と生成物を共有しない。
- Next.js 16.1.6の開発時に起きるInterceptionリライトの重複にはpnpmパッチを適用した。発生条件、対策、更新時の扱いは [Next.js 16.1.6 の Intercepting Routes 開発時不具合](../nextjs-interception-hmr-workaround.md) を参照。パッチ適用後、2回のファイル保存後も2ペイン表示を確認し、開発サーバー再利用のルーティングE2E 7件が成功した。
