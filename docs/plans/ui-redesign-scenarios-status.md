## 統合前に確定する仕様

| 項目 | 計画と実装の差 | 再開時の扱い |
|---|---|---|
| 目次 | 計画は目次とセクション配列の共有を要求。パネル実装は目次を置かず、ページ側で検討する構成 | パネル・単独ページごとの採否を確定する。現在未使用であることだけを理由に完了扱いにしない |
| 検索項目 | 計画は基本行にシステム・カテゴリ、詳細にHO公開を記載。現部品は基本行がキーワード、詳細がシステム・タグ・人数・時間 | 現在の検索契約と照合して今回の対象を明記する。未接続の検索項目を見た目だけ追加しない |
| 表示形式 | 計画にカード／リスト切替があるが、一覧パネルに切替はない | 今回含めるか後続にするか確定し、計画と受入条件を揃える |
| タグ色 | 計画はカテゴリ別トークンを検討。実装はDBの色を受け取る `Tag` | 実装済みのデータ駆動方式を前提に計画を更新する |
| パネル幅 | Storyは1:1配置・最小幅1100px | SideMenuを含む使用可能幅で単独／2ペインの切替点を決める。Storyの固定幅をそのまま実画面に移さない |
| 戻る・閉じる | 新パネルのリンク先は固定の `/scenarios` | 検索条件、追加読込済み結果、スクロール、発火元へのフォーカスが保持される遷移を設計する |

検索・一覧・2ペインのStoriesは `useFilterDraft` と `NuqsTestingAdapter` を使い、入力・検索・クリア・並び順・追加読込で状態が変化する。検索結果はStory専用の固定データから生成するため、検索APIやDBの正しさを証明するものではない。キーワードの対象は現行APIに合わせてシナリオ名とし、入力の案内も「シナリオ名」に揃えている。

## 再開する順序

### 1. コンポーネントテストの実行環境（完了）

`.storybook/vitest.setup.ts` で `next/font/google` のビルド処理だけをモックし、Vitestが `Noto_Sans_JP is not a function` で停止する問題を修正した。Storybookのpreviewには実フォントを維持している。

- `SideMenu` / `SectionToc` / `Pill` / `Tag` / `Divider` の5ファイルを含め、コンポーネントテスト全体が実行可能。
- 型チェック、Storybookビルド、ブラウザーでの実フォント適用を確認済み。
- 今回の修復に伴うテストのスキップ追加はない。

### 2. 部品の操作と表示（現行契約の検証完了）

- Vitestを50件追加。検索の下書き・確定・クリア・URL同期、並び順、追加読込、空状態・読込中、認証別表示、キーボード操作を確認。
- 詳細では画像なし・長文・データなし、リンク、ネタバレ表示、お気に入りの成功・失敗・再試行・二重送信防止を確認。
- Playwrightを7件追加。詳細を320 / 390 / 600 / 1280px幅で確認し、モバイル検索、保存失敗後の再操作、空白のない長文の欠けを検証。
- Storybookの一覧・詳細・2ペインの表示を確認。320pxで詳細の操作ボタンが欠ける問題は折り返しで修正。
- 目次、カテゴリ・HO公開フィルター、カード／リスト切替、実画面のパネル幅は「統合前に確定する仕様」に残る。今回の部品検証では追加仕様を確定していない。

検証に伴い、キーワードだけ入力した際のクリア表示、クリア後に遅延更新が復活する競合、外部から変更した人数・時間とスライダーの表示のずれ、空状態からのリセットで下書きが残る問題も修正している。

### 3. 実画面に一覧パネルとSideMenuを接続する

- `ScenariosContent` が持つ `useFilterDraft`、URL同期、検索結果、追加読込を保ち、表示を `ScenarioListPanel` に接続する。モバイル検索の入口も維持する。
- 旧 `SearchSidebar` / `SearchTopBar` 等は、参照と対応テストの移行を終えてから削除する。
- `SideMenu` をメインレイアウトに接続し、GlobalHeaderのログイン・登録・プロフィール等の導線を照合する。
- ヘッダーのPC表示を切り替える際に、home / scenarios / sessions / schedules / users / feedback / profile と動的ルートの余白・スクロールを確認する。
- 検索・フィルターのE2E/POMを実際のアクセシブル名に合わせて更新する。

### 4. 詳細のデータ取得を共通化して、新パネルを接続する

- `[id]/page.tsx` から認証・詳細データ・ユーザー状態の組み立てを共通ViewModelに抽出する。
- 既存の取得順序とサーバー側の認証・権限確認を維持し、Server Actionを共有する。
- まず単独の詳細ページを `ScenarioDetailPanel` に接続し、現在の表示内容と操作が欠落していないことを確認する。
- お気に入りのコールバックは、成功時に確定した `isFavorite` を更新し、失敗時にPromiseをrejectする契約。現在のページ側はServer Actionの `{ success: false }` を破棄するため、パネル接続時に必ず失敗を変換する。
- 動画・レビューの投稿、編集、追加読込のハンドラーを実画面へ接続する。Storyでの表示・コールバック検証だけで、投稿機能の完成としない。

### 5. 2ペインのルーティングと回帰テストを完成させる

- Parallel / Intercepting Routesを接続し、一覧クリック、直URL、リロード、戻る／進む、閉じるを検証する。
- 詳細を閉じても検索条件、一覧結果、追加読込分、スクロール位置が保持されることを確認する。
- モバイルの単独表示、パネル間のキーボード操作、開閉時のフォーカス移動を確認する。
- データなし、存在しないID、取得失敗、未ログイン、お気に入り操作を含む関連E2Eを実行する。
- 型・lint・本番ビルドと関連テストの結果を揃えてから統合完了とする。
