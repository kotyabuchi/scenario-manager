## 議論サマリー

### 合意点（初回で一致、即採用）

- C-3 + A-1: cleanup に `session_availability_time_blocks` / `game_schedule_time_blocks` 削除が欠落 → Step 1-0 追加

### ラリーの記録

#### C-2: モバイルビューポートでのリンク表示問題
- **R1 Codex**: モバイルではリンクがメニュー集約されるため、テスト前提が崩れる（高）
- **R1 Claude**: Playwright デフォルト viewport は 1280x720。デスクトップ前提で十分。
- **R2 Codex**: 【修正】viewport 前提を計画に明記すべき。強度は下げる。
- **結論**: 修正して採用（決定事項に viewport 前提を追加）

#### C-5: 日程確定アクション成功テスト欠落
- **R1 Codex**: ボタン表示確認だけでは確定アクションの回帰検知ができない（中）
- **R1 Claude**: GM 単独ではデータ不足で候補生成されない可能性。代替フロー実現可能性は？
- **R2 Codex**: 【維持】datetime-local → 確定 → 成功メッセージ確認は実現可能。
- **R2 Claude**: 合意。RECRUITING → スケジュール提出 → PREPARATION → 日程確定の一連フローを追加。
- **結論**: 採用（ライフサイクルテストにスケジュール提出→確定フローを統合）

#### C-6: Review Checkpoint 未定義
- **R1 Codex**: plan-mode.md 必須の Review Checkpoint が未定義（中）
- **R1 Claude**: exec-plan スキルが自動処理するため明記不要。
- **R2 Codex**: 【修正】exec-plan 前提であることを1行明記すべき。
- **結論**: 修正して採用（検証方法に1行追記）

#### C-1 cleanup 粒度
- **R1 Codex**: spec ごとに session_id を追跡し、そのIDのみ削除すべき
- **R1 Claude**: 既存の `[E2E]` プレフィックスパターンで十分。一貫性を優先。
- **R2 Codex**: 【修正】既存パターンと整合するなら撤回。serial 化は維持。
- **結論**: cleanup 粒度は却下。serial 化のみ採用。
