## 議論サマリー

### 合意点（初回で一致、即採用）

- C-4/A-4: スマートフィルタをデフォルトOFFにする

### ラリーの記録

#### C-1: scenarioId の Zod スキーマ
- **R1 Codex**: ULID regex + 存在確認を要求
- **R1 Claude**: プロジェクトの既存パターン（linkId 等）と不整合。DB FK制約で担保する設計
- **R2 Codex**: 【修正】ULID regex は撤回。空文字/空白正規化 + FK違反時のエラーマッピングに変更
- **結論**: 修正して採用（trim().min(1) + FK違反時のエラーメッセージ）

#### C-3: ScenarioSearchModal 共通化
- **R1 Codex**: sessions/_shared/ に即時切り出しを提案
- **R1 Claude**: 5ファイル以上の移動でスコープ超過。直接 import で対応
- **R2 Codex**: 【修正】即時共通化→別タスク化（TODO化）に変更
- **結論**: 修正して採用（計画書に技術的負債として明記）

#### C-5: Action テスト
- **R1 Codex**: actions.test.ts の追加を要求
- **R1 Claude**: プロジェクトに Action テストの前例なし。パターン信頼の設計
- **R2 Codex**: 【修正】新規導入は撤回。Adapter テスト強化 + 手動検証で対応
- **結論**: 修正して採用（既存パターン踏襲）

#### A-2/D-4: フェーズガード
- **R1 Claude**: COMPLETED/CANCELLED でシナリオ変更を許可すべきでない
- **R2 Codex**: 【維持】フェーズガード必要
- **結論**: 採用（RECRUITING/PREPARATION のみ許可）
