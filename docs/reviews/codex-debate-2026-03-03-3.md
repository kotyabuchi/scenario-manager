### ラリーの記録

#### C-1: サーバー側KEEPER重複チェック
- **R1 Codex**: `hasKeeper` でUI非表示だけでは不十分、`applyToSession` に必須バリデーション化を
- **R1 Claude**: 妥当だがフロントエンドUIリファクタリングのスコープ外。留意事項として記載で十分か？
- **R2 Codex**: 【修正】スコープ外は認めるが、「留意事項」ではなく「リリース前の依存タスク」として明記すべき
- **結論**: 採用（修正版）— 留意事項セクションに「リリース前必須の依存タスク」として追記

#### C-2: DB enum マイグレーション手順
- **R1 Codex**: マイグレーション/型再生成手順が欠落
- **R1 Claude**: `src/db/types.ts` で KEEPER 確認済み、マイグレーション不要。前提条件の読み飛ばしでは？
- **R2 Codex**: 【修正】マイグレーション必須は強すぎた。DB実体との整合確認手順を1行入れれば安全
- **結論**: 一部採用 — 前提条件に「DB実体も同期済み」と補足追記

#### C-3: toLocaleDateString のTZ依存
- **R1 Codex**: SSR/CSR不一致のリスク
- **R1 Claude**: 既存パターン（BasicInfoSection.tsx の formatDate）と一貫性を優先すべきでは？
- **R2 Codex**: 【修正】既存パターンに合わせる方が妥当。TZ統一は別タスクで横断的に実施
- **結論**: 却下（Codex 自身が撤回方向に修正、既存パターン準拠）

#### C-4: コンポーネントテスト追加
- **R1 Codex**: UI変更が大きいのにSchemaテスト中心
- **R1 Claude**: プロジェクト方針としてダイアログにユニットテスト不使用。E2Eで検証
- **R2 Codex**: 【修正】方針尊重。E2Eでの回帰ケース明記を推奨
- **結論**: 却下（プロジェクト方針準拠、E2Eは別タスクスコープ）

#### C-6: Batch 2 再分割
- **R1 Codex**: 200+行を一括変更するとレビュー性が落ちる
- **R1 Claude**: 3ファイル200行は粒度ガイドライン内。密結合で分割するとビルド不整合リスク
- **R2 Codex**: 【修正】再分割は必須ではない。実施順と中間チェックポイントの固定を推奨
- **結論**: 却下（粒度ガイドライン内、Step 順序は既に明確）
