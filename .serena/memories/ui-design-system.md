# UIデザインシステム

本プロジェクトのUIデザイン仕様。**UI実装時は必ずこのファイルを参照すること。**

> **コンポーネントの詳細な挙動**（ホイール操作、キーボード操作等）は `ui-component-behavior` メモリを参照。

テーマ: **モダン × ソフト × レイヤードUI** - 淡い緑みがかった白背景、カスタムブランドグリーン（#059568）ベース

---

## 1. カラーパレット（最重要）

**カラーの正は `src/styles/tokens/colors.ts`（OKLCH直書き）**。全ファミリーで同一の L/C ランプを共有し、色相(H)だけ変える「同一トーン」設計。基準 primary.500 = `oklch(0.674 0.103 148)`（≒#68A872、モックの登録ボタン採取色）。

> ⚠️ 以下のHEX値は**旧パレットの参考**で現行とは異なる（色味・形式とも）。実値は必ず colors.ts を参照し、ここに重複させない。

### トークンの2層構造（厳守）

色は必ずトークンで定義し、コンポーネントに生の色値をハードコードしない。トークンは **2層** に分け、役割を混ぜない。

| 層 | ファイル | 役割 | 命名 | 値の形式 |
|----|---------|------|------|---------|
| **base（`colors`）** | `src/styles/tokens/colors.ts`（+`colorValues.ts`） | **ベースカラーの定義そのもの**。色相・明度のパレット。意味は持たない | 色相＋段階（`green.500`, `gray.100`, `paperBorder.50`） | **すべて OKLCH** |
| **semantic（`semanticTokens`）** | `src/styles/semanticTokens.ts` | base に **意味・役割を与えた別名**。コンポーネントはこちらを参照 | 用途・役割（`bg.card`, `text.body`, `border.default`） | base への参照（`{colors.green.500}`） |

- **`colors` と `semanticTokens` は別物**。`colors` は「どんな色があるか」、`semanticTokens` は「その色を何に使うか」。semantic は必ず base を参照し、semantic に生の OKLCH を直書きしない。
- コンポーネントが参照するのは原則 **semantic トークン**（意味）。base を直接参照するのは、意味付けが不要な純粋な色相利用（例: `systemBadge.green`）に限る。

### トークン追加ルール（乱立の再発防止）

> 背景: 整理前は **同じカラーコードのトークンが各所に乱立**していた（同じ色を別名で何度も定義）。これを繰り返さないための追加基準。

1. **まず既存で賄えないか探す**。新色を足す前に、`get_tokens` / `get_semantic_tokens`（PandaCSS MCP）や既存トークンで代用できないか必ず確認する。
2. **その追加は本当に必要か問う**。既存の役割トークンに寄せられるなら追加しない。「この画面専用」の色を増やさない。
3. **base への追加は OKLCH で**、同一 L/C ランプ・同一トーン設計を崩さない（色相のみ変える）。
4. **semantic の命名は汎用的・カテゴリー的に**。詳細で固有の名前（`scenarioDetailHeadDivider` 等）は避け、**再利用できる役割名**（`border.subtle`, `bg.card`, `text.secondary` 等）を付ける。1コンポーネント専用に見える名前は乱立の予兆。
5. 迷ったら**役割の粒度を上げて共有**する（「シナリオ詳細の枠線」ではなく「カード面の枠線=`paperBorder`」）。

## 3. コンポーネントパターン

### カード（レイヤードカード / 2026-07 更新）

```typescript
{
  bg: 'card.bg',              // paper（淡い緑みの白）。純白ではない
  borderWidth: '1px',
  borderStyle: 'solid',
  borderColor: 'paperBorder.50',  // 薄い緑みグレー枠。内側サブカードは paperBorder.100
  borderRadius: '2xl',       // 16px
  overflow: 'hidden',
  boxShadow: 'card.default',  // 0 4px 16px（薄影で浮遊感）
  transition: 'all {durations.slow} ease',
  _hover: {
    boxShadow: 'card.hover',  // 0 8px 24px
    transform: 'translateY(-2px)',
  },
}
```

**重要（更新）**: カード面は **`paper` 背景 ＋ `paperBorder` 薄ボーダー ＋ ソフト影の併用**（レイヤードカード）。旧「border は使わず影のみ」から変更。ごく薄い緑みグレー枠で面の輪郭を締めつつ、影で浮遊感を残す。border 値は必ず `paperBorder.*` トークンを参照（ハードコード禁止）。

> 実装参照: `src/app/(main)/scenarios/[id]/_components/ScenarioDetailPanel/styles.ts`（`mainCard` / `sectionCard` / `head`）。
> **追従漏れ**: 一覧の `ScenarioCard` は現状まだ純白＋影のみ・ボーダーなし。新方針への移行は別タスク。

## 4. 禁止パターン

| 禁止 | 理由 | 代替 |
|------|------|------|
| 生の色値をコンポーネントに直書き | 一貫性が崩れる | トークン名を参照。**カラートークン本体（colors.ts）は OKLCH で定義**するのが現行方針（旧HEX禁止は撤回）。DB動的色は Tag→Pill tone="custom" |
| カード輪郭に `1px solid #...` をハードコード | 一貫性が崩れる | **カード面は `paperBorder.*` 薄ボーダー ＋ `card.default` 影を併用**（トークン参照。生値の直書き禁止） |
| ハードコードされた色を直接使用 | 一貫性が崩れる | セマンティックトークンを使用 |
| `w: '48px', h: '48px'` でアイコンサイズ | ページ間で不統一 | `fontSize` トークン |
| Tailwindカラー値の使用 | 実装はカスタムパレット | `colors.ts`の値を使用 |

## 6. 設計原則

### デザインコンセプト

**モダン × ソフト × レイヤードUI**

| 原則 | 説明 |
|------|------|
| レイヤードカード（更新） | **カード面は `paper` 背景 ＋ `paperBorder` 薄ボーダー ＋ ソフト影を併用**（ごく薄い緑みグレー枠＋浮遊感）。旧「カードはボーダーレス・影のみ」から更新。border が最適な他の箇所（フォーカスリング/入力欄/高密度な表の区切り/同一elevation面の境界/半透明・画像上の輪郭/選択強調）も意図的に使ってよい。判断基準=浮かせたい:影/同高さで区切り:border。border はトークン参照（カード面=`paperBorder.*` / 汎用=`border.*`・`borders.soft`。ハードコード禁止） |
| ソフト | 角丸、柔らかい影で優しい印象 |
| レイヤード | 影の強弱＋薄ボーダーで奥行きと階層を表現 |
| 淡い背景 | ページは `canvas`、カード面は `paper`（いずれも淡い緑みの白）でコンテンツを引き立てる |

### インタラクション

- **ホバー**: `translateY(-1〜2px)` + 影の強調
- **トランジション**: `all {durations.slow} ease`（カード）、`all {durations.normal} ease-in-out`（チップ）
- **フォーカス**: 2px のフォーカスリングで明示

### アクセシビリティ（WCAG AA）

- 通常テキスト: コントラスト比 4.5:1 以上
- 大きいテキスト: コントラスト比 3:1 以上
- UIコンポーネント: コントラスト比 3:1 以上
